# LLM 韧性治理未来演进候选

- **日期**：2026-06-20
- **变更原因**：`plan_7` 明确一期不实现自动重试、熔断和多供应商降级，但需要记录这些能力进入后续规划的事实门槛，避免在 Provider Adapter 中留下无归属 TODO 或提前构建无数据支撑的抽象。
- **关联提交**：本次 `plan_7` 计划提交（同提交创建）

## Before（变更前）

`plan_main` 没有记录 LLM 供应商故障、限流、超时和成本问题达到何种条件后才进入工程治理。后续实现者可能直接增加重试或降级，也可能留下没有具体 Plan 归属的 TODO。

## After（变更后）

`plan_main` 将 LLM 韧性治理记录为未来演进候选。只有真实运行数据证明认证外故障、限流或超时形成稳定问题后，才创建独立主 Plan 评估限次重试与退避、熔断和超时隔离、多供应商降级、请求幂等、成本及延迟控制。

该候选不进入当前执行队列，也不授权 `plan_7` 实现重试、Fallback 或多供应商抽象。

## 影响范围

- 受影响的 Plan：`plan_7`
- 受影响的模块：未来可能涉及 `crag-query`，本次不修改运行时代码
- 受影响的约束：无

## 迁移与兼容

现有实现无需迁移。`plan_7` 保持单 Provider Adapter、零自动重试和失败直接返回 502 的边界；未来只有创建并提交新的主 Plan 后才能改变该策略。

## 回滚可能性

该变更仅增加方向记录，无运行时、数据或接口影响。若后续决定不保留该候选，可在新的方向决策中删除 `plan_main` 对应段落并归档撤销原因。
